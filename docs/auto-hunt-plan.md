Обновляется по фактическим проверкам. Приоритет — самостоятельная охота во всех стартовых
областях. Следующую задачу брать после проверки текущей; наличие кода не равно принятому поведению.
Уточнение владельца 03.11: сначала довести до приёмки базовую автоохоту (пункт 18).
Онлайн-авторежим и прочие дополнительные блоки выполнять после этого, не подменяя
ими оставшиеся проверки и исправления охоты.
Исторический аудит: [movement-audit-2026-11-01.md](movement-audit-2026-11-01.md).
Завершённый первый блок: [PR #66](https://github.com/zabozhane/myl2ai/pull/66).
Следующие законченные задачи публиковать отдельными PR с результатами проверок.

## Порядок проверок

- После небольшой правки: сборка и короткая адресная проверка изменённого правила/сбоя.
- После законченного блока связанных изменений: один реальный полный прогон сценария.
- Длительную приёмку выполнять в фоне параллельно следующим последовательным
  исправлениям: фиксировать образ/исходную точку, не менять проверяемую сборку до
  конца окна. Новые исправления проверять на отдельном стенде. Рестарт/смена образа
  завершает окно с явной отметкой; итоговую приёмку проводить на окончательной сборке.
- Длинное наблюдение полного цикла — в конце блока/этапа. Изменение только бюджета или
  таймера не требует повторять многоминутную дорогу без новой причины для регрессии.
- При изменении движения/восстановления обязательны реальное прибытие и продолжение занятия.
- Ситуации на изолированной копии должны переиспользоваться: нет денег, недоступный путь,
  кончились расходники, возврат после смерти. В чистой логике время подставляется, не ожидается.
- Успех/отказ определяются автоматически по результату; сценарий заканчивается сразу после
  проверки. Фиксируется конкретная собранная версия; геодата включена, боевые проверки без GM-защиты.
- Общие изменения проверяются для населения и Zenthen. Полный цикл Zenthen с городскими
  делами, снабжением и возвратом остаётся обязательной приёмкой этапа.

## Проверено и установлено

1. Общая диагностика перемещений: отказы по персонажам/целям, периоды без движения,
   минутные состояния молчащего населения. Наблюдение простоя требует проверки причины.
2. Исключения неудачных спотов не обходятся запасным выбором; повтор поиска ограничен паузой.
3. Общий ходок и офлайн-возврат проверяют геодату и опасности каждого участка; фиксируют
   отсутствие продвижения независимо от флага движения, имеют конечный бюджет маршрута.
   Проверены NPC в трёх деревнях, узкий угол и возврат из орочьей деревни.
4. Поездки используют реальное меню доступного гейткипера и оплату ядром. Учитель сначала
   местный; произвольный бесплатный телепорт из мирового списка исключён.
5. Восстановление застрявшего Zenthen: поиск за пределами первых пяти отказавших кандидатов,
   безопасный дальний маршрут с бюджетом по его длине. Обычный персонаж дошёл и получил опыт
   100589 → 101087 без расхода SoE; после установки на основном сервере достиг 12-го уровня.
6. Плановые городские дела ждут полезной охоты, срочное лечение/перегруз обрабатываются отдельно.
   Причины SoE записываются. Дальний возврат после городских дел также имеет рассчитанный бюджет.
7. Подготовленный новичок может потратить остаток денег на реальный проезд; запас лечения и SoE
   проверяются. Один запасной SoE вместо двух. Проверена реальная закупка и поездка за 610 аден.

8. Узкие выходы и рампы: уточнять неудачный крупный поиск в пределах конечного времени,
   сохраняя проверки стен, высоты и опасностей. Проверка `VILLAGE EXIT ALL PASSED`:
   BlackForce и JetixmAX получают пути из точных позиций, BlackForce реально прошёл за 238 с
   и получил опыт в обычном бою. Прежняя сборка воспроизводимо отказывает ещё при планировании.
   Установлена проверенная сборка. Случай sdf остаётся открытым.
